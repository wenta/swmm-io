# Binary `.swmxidx` sidecar format v1

This is a private optional companion format for *one* SWMM result channel. The index is not an alternative to a SWMM `.out` and is not generated by EPA.

The binary format is little-endian and versioned:

| Byte offset | Field |
|---:|---|
| 0 | 8 ASCII bytes `SWMXIDX1` |
| 8 | uint32 LE metadata JSON byte length |
| 12 | UTF-8 JSON (version, source key, layout, request, reporting periods, tree capacity) |
| after JSON | Zero-padding to 4-byte boundary |
| payload | Float32Array minima, Float32Array maxima, Uint32Array minimum period, Uint32Array maximum period, in that order |
| final 4 | uint32 LE CRC32 over bytes `[8, last-4)` |

The complete binary tree uses the conventional heap layout with element zero unused: capacity is the next power of two at least equal to the reporting period count; leaves start at `capacity` and internal nodes occupy `[1,capacity)`. Each node is stored in **four corresponding arrays**. Leaf indices represent original zero-based reporting periods; `0xffffffff` marks a subtree with no finite value. Unused leaves are empty. Interior `NaN`/Infinity samples do not influence finite extrema but the leaf minimum array retains the original non-finite value for endpoint fidelity.

On load, the reader checks the file magic, version, CRC, metadata length, sourceKey, source structural layout, range pointers and array sizes. These checks catch corruption and likely mismatches. The `sourceKey` must be authenticated/managed by the application; the structural layout alone is **not** enough to distinguish two different SWMM simulation runs. CRC32 is not cryptographic authentication. Never accept untrusted sidecars merely because they pass CRC.

The index data is allocated and maintained on demand. The library does not automatically create sidecars or keep them on disk. An API service may choose an external on-disk cache with a content-addressed key, but should never rely on user filenames as identity.

The binary format can change in future major releases; readers reject unsupported versions. It is part of the `swmm-io` project, not an official SWMM/EPA standard.
